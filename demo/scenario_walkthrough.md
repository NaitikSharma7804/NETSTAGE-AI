# NetSage AI - 5-10 Minute Demonstration Script

## Demo Overview
This script guides a presenter through showcasing the full NetSage AI workflow:
**BROKEN NETWORK ➔ EVIDENCE ANALYSIS ➔ DETERMINISTIC VALIDATION ➔ AI INFERENCE ➔ EVIDENCE FUSION ➔ HUMAN REVIEW (ACCEPT & EDIT) ➔ MANUAL FIX ➔ VERIFICATION ➔ ANALYTICS & AUDIT**

---

### Step 1: Launch Services
1. Start FastAPI Backend:
   ```bash
   uvicorn backend.main:app --port 8000
   ```
2. Start Streamlit Dashboard:
   ```bash
   streamlit run dashboard/app.py
   ```
3. Open `http://localhost:8501`.

---

### Step 2: Home Page Presentation (1 Minute)
- Point out the **Executive Metric Cards** (40 Cases, AI Agreement Rate, Human Reviews, Verification Rate).
- Explain the **Core Philosophy**: *"AI ASSISTS. RULES VALIDATE. HUMANS DECIDE. VERIFICATION CONFIRMS."*
- Highlight why NetSage AI is **NOT** a generic chatbot: it is an evidence-driven diagnostic platform combining deterministic rule validation and human oversight.

---

### Step 3: Standard Troubleshooting Scenario - Case `NS-ACL-001` (2 Minutes)
1. Navigate to **🔍 Troubleshoot & Diagnose**.
2. Select `NS-ACL-001 - VLAN 30 PC Cannot Reach Server Due to Implicit Deny`.
3. Highlight the observed symptom: PC in VLAN 30 can ping gateway but cannot reach Server in VLAN 10.
4. Click **🚀 Run Diagnosis & Evidence Fusion**.
5. Show:
   - **Deterministic Rule Engine**: Flags ACL packet drops and implicit deny counters.
   - **AI Diagnosis**: Correctly isolates standard ACL `BLOCK-OLD` implicit deny on subinterface Gi0/0.10.
   - **Cited Evidence**: References `show access-lists` match counters.
   - **Fix Recommendation**: `permit 192.168.30.0 0.0.0.255`.
6. **Human Review**:
   - Choose **ACCEPT**.
   - Enter rationale: *"Confirmed implicit deny match on ACL BLOCK-OLD."*
   - Click **Submit & Record Human Review**.
7. **Fix Verification**:
   - Enter verification ping test `5/5 100% success`.
   - Choose **PASS** and submit.

---

### Step 4: Responsible AI Human Correction Scenario - Case `NS-DNS-004` (2 Minutes)
1. On the Troubleshoot page, select `NS-DNS-004 - UDP Port 53 Blocked by Perimeter Firewall ACL`.
2. Check the box: `🧪 Simulate AI Edge Case / Misdiagnosis (Demonstrates Human Correction)`.
3. Click **Run Diagnosis**.
4. Show that the AI incorrectly diagnosed an external DNS server outage.
5. Demonstrate the **Human Safety Gate**:
   - Select **EDIT**.
   - Enter Corrected Root Cause: *"Firewall extended ACL 'OUTSIDE-IN' permits TCP 53 but denies UDP 53 return traffic."*
   - Enter Technical Rationale: *"Show access-lists showed rule 10 only permitting TCP 53 while UDP DNS queries hit rule 30 deny."*
   - Submit the correction.
